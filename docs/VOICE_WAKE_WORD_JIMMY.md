# Wake-word «Джимми»: техническое решение и план проверки

## Выбор первого прототипа

Для русской фразы «Джимми» первым проверяем Vosk с моделью `vosk-model-small-ru-0.22`.

Почему:
- модель официально обозначена как небольшая модель для Android/iOS/Raspberry Pi;
- размер архива около 45 MB;
- ориентировочное потребление памяти во время работы около 300 MB;
- лицензия модели указана как Apache 2.0;
- Vosk поддерживает dynamic vocabulary/grammar для small-моделей;
- Android API позволяет создавать Recognizer с ограниченной grammar и принимать PCM-поток.

Это не специализированный keyword spotter. Это локальное потоковое распознавание с ограниченной грамматикой, выбранное как более прямой путь для русской фразы. До измерений на устройстве не считать его готовым wake-word решением.

Официальные источники:
- https://alphacephei.com/vosk/models
- https://github.com/alphacep/vosk-android-demo
- https://github.com/alphacep/vosk-api
- https://alphacephei.com/vosk/android

## Архитектура

1. Модель загружается по требованию в приватную папку приложения, а не включается в APK.
2. Перед распаковкой проверяется HTTPS-ответ, ожидаемое имя архива, размер и структура ZIP; распаковка должна блокировать path traversal и выполняться через временную папку с атомарным перемещением.
3. В режиме ожидания AudioRecord подаёт mono PCM 16 kHz в Vosk Recognizer с ограниченной грамматикой wake-фразы «джимми».
4. После обнаружения wake-фразы сервис переходит в режим команды и использует распознаватель с обычным словарём.
5. После завершения ответа и периода тишины сервис возвращается к ограниченной wake-грамматике.
6. Пока ассистент говорит через TTS, микрофон должен быть приостановлен или защищён от акустической обратной связи.
7. В любой момент пользователь может остановить прослушивание из UI или постоянного уведомления.

## Состояния диалога

- STOPPED — микрофон закрыт.
- WAKE_LISTENING — слушает только wake-фразу.
- COMMAND_LISTENING — распознаёт команду после активации.
- THINKING — выполняется запрос к локальной или облачной модели.
- SPEAKING — воспроизводится TTS; распознавание не должно принимать собственный голос.
- TIMEOUT — после тишины возврат в WAKE_LISTENING.

Повторять «Джимми» внутри уже активного диалога не требуется. Имя нужно только для выхода из ожидания.

## Android ограничения

- Для фонового микрофона нужен отдельный foreground service типа `microphone`, соответствующее разрешение и постоянное уведомление.
- Сервис должен запускаться из видимой активности после явного разрешения пользователя.
- Android и энергосбережение Samsung могут остановить или ограничить фоновое прослушивание. Не обещать работу после force-stop, отзыва разрешения или агрессивного энергосбережения.
- Wake-фраза не является биометрической аутентификацией и не даёт право выполнять опасные действия.

## Приёмочные тесты на SM-S711B / Exynos 2200

До включения always-on режима собрать тестовую выборку:
- 30 произнесений «Джимми» самим владельцем: тихо, нормально, громко, с разных расстояний.
- 30 отрицательных примеров: обычный разговор, похожие слова, телевизор, музыка, тишина и бытовой шум.
- Проверить ложные срабатывания в течение минимум 30 минут фонового теста.
- Замерить CPU, RAM, задержку детекции, расход батареи и нагрев.
- Проверить остановку/возврат после TTS, блокировки экрана, сворачивания приложения и отключения микрофонного разрешения.

Пороговые значения для первого прототипа:
- wake recall не ниже 90% в тихой комнате на обычной громкости;
- ни одного ложного срабатывания на 30-минутном отрицательном тесте;
- средняя задержка активации до 1.5 секунды;
- память процесса wake-модуля около или ниже 350 MB;
- CPU и батарея измеряются отдельно на устройстве, не оцениваются по desktop build.

Если тесты не проходят, не включать постоянное прослушивание по умолчанию. Пересмотреть грамматику, аудио-предобработку или специализированную модель.
