# Удалённая runtime-конфигурация

## Текущее состояние

Android-клиент получил ручное обновление runtime bundle из GitHub Raw. После установки APK с загрузчиком пользователь открывает **Настройки → Скачать обновления конфигурации**. Автоматического фонового обновления пока нет.

Источник:
`https://raw.githubusercontent.com/mikhaildezprofi-glitch/mobile-ai-agent/sync/current/runtime-config/manifest.json`

GitLab main остаётся единственным источником изменений. GitHub `sync/current` — опубликованная копия runtime bundle.

## Что делает текущий загрузчик

1. Получает manifest только с закреплённого HTTPS-адреса.
2. Проверяет версию схемы, доверенный base URL и запрет секретов/исполняемого кода.
3. Загружает 18 JSON/TXT файлов по фиксированному списку manifest.
4. Ограничивает размер одного файла 256 KiB, общий размер 512 KiB.
5. Проверяет SHA-256 каждого файла до активации.
6. Проверяет JSON-синтаксис и допустимые имена текстовых prompt-файлов.
7. Сначала пишет набор в staging-каталог, затем переключает `files/runtime-remote/current`.
8. Сохраняет предыдущий bundle в `files/runtime-remote/previous`.
9. Не отправляет API-ключи, пользовательские файлы или данные чатов на сервер.

Если пользовательский системный промпт не редактировался вручную, загрузчик применяет основной профиль `assistant_ru`. Если пользователь сохранил собственный текст, он остаётся без изменений.

## Что уже можно менять без APK после установки загрузчика

- основной системный промпт;
- JSON/TXT bundle и профили промптов, которые уже известны установленной схеме;
- каталог моделей, параметры маршрутизации, privacy, voice, network, diagnostics и response profiles — они скачиваются и проверяются, но не все параметры пока подключены к логике приложения.

После следующего APK-клиента активируются параметры, для которых в нём уже есть реализация:
- выбор одного из prompt-профилей из `prompts/index.json`; пользовательский системный промпт сохраняется отдельно и имеет приоритет, пока пользователь сам не выберет профиль;
- выбор response-профиля из `response_profiles.json`, включая лимит выходных токенов и температуру для Gemini;
- `routing.json`: предпочтительные cloud-задачи, локально-обязательные задачи, локальный fallback, лимиты токенов и флаг доступности поиска;
- `modules.json`: включение/выключение вложений, микрофона, камеры, чтения документов, извлечения кадров видео, локального vision и Gemini API. Явные локальные переопределения пользователя сохраняются отдельно; кнопка сброса возвращает управление серверным значениям;
- `models.json`: Gemini model ID;
- `network.json`: сетевые тайм-ауты Gemini;
- `voice.json`: язык распознавания речи;
- `ui.json`: тексты placeholder, лимит длины запроса и число вложений;
- `diagnostics.json`: доступность раздела диагностики.

Флаги веб-поиска, управления Android, wake word «Джимми» и TTS не включают отсутствующую реализацию. Эти функции остаются недоступными, пока не будут добавлены в APK. Локальная температура Qwen не меняется этим JSON, поскольку текущий native API не предоставляет настройку temperature.

## Что требует APK

- новый Kotlin/Java-код и Compose UI;
- новые Android permissions, services, activities и receivers;
- JNI, llama.cpp, native libraries;
- новые SDK, библиотеки и сетевые протоколы;
- новая логика, которой ещё нет в установленном клиенте.

Удалённый bundle не может загружать или исполнять DEX, JAR, APK, SO, скрипты или другой код.

## Файловая структура и контроль целостности

- `manifest.json` содержит версию, доверенный base URL, перечень файлов и SHA-256.
- `sha256` покрывает все пути из `files`.
- `scripts/validate-runtime-config.py` проверяет существование файлов, безопасность путей, JSON-схемы и совпадение SHA-256.
- Размеры и типы файлов повторно проверяются самим Android-клиентом, а не только CI.

Manifest доставляется по HTTPS; SHA-256 защищает файлы от случайного повреждения или подмены относительно manifest. Это не цифровая подпись manifest: для защиты от компрометации самого источника в дальнейшем следует добавить подпись manifest публичным ключом, встроенным в APK.

## Ограничения и следующий этап

- Загрузчик проверяет `minimumAppVersion`, но не выполняет автоматическое обновление при запуске.
- Каталог `previous` сохраняется, но пользовательский интерфейс отката ещё не добавлен.
- Автоматическое обновление при запуске отключено параметром `checkOnLaunch=false`; обновление запускается вручную.
- Подпись manifest публичным ключом APK и пользовательский rollback UI остаются отдельными задачами.
- Перед объявлением функции готовой нужны успешная GitHub Actions сборка, проверка подписи APK и тест на Samsung S23 FE.

## Правило сборок

Изменения только в `runtime-config/**`, `docs/**` и проверочных скриптах не должны запускать APK build. Android/Kotlin/Compose, Gradle, JNI и native изменения требуют сборки. Sync workflow сравнивает изменения с последней успешной сборкой и учитывает уже выполняющуюся сборку, чтобы не запускать дубликат из-за поздних документационных коммитов.
