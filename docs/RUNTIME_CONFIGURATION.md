# Удалённая runtime-конфигурация

## Назначение

Каталог `runtime-config/` содержит версионируемые JSON-настройки и текстовые промпты. Он подготовлен для загрузки приложением без публикации нового APK после того, как в Android-клиент будет включён загрузчик удалённой конфигурации.

**Текущее ограничение:** установленная версия приложения читает файлы из приватного каталога `files/runtime/`. Она пока не загружает этот каталог из GitLab/GitHub автоматически. Поэтому сами файлы в репозитории не меняют поведение уже установленного APK.

## Источник конфигурации

После синхронизации GitLab → GitHub bundle доступен по HTTPS через стабильную ссылку:
`https://raw.githubusercontent.com/mikhaildezprofi-glitch/mobile-ai-agent/sync/current/runtime-config/manifest.json`.

Клиент должен использовать только baseUrl из встроенного доверенного источника, а не произвольный URL из самой конфигурации. Ссылка на ветку `sync/current` обновляется sync workflow после изменения GitLab main.

## Что планируется обновлять без APK

- системные промпты и профили ответов;
- параметры генерации и маршрутизации уже встроенных провайдеров;
- UI-тексты и поддерживаемые настройки интерфейса;
- флаги уже реализованных модулей;
- каталог моделей, подсказки и лимиты;
- фразы команд, которые уже сопоставлены с безопасными действиями приложения.

## Что не получится включить одной конфигурацией

Новый Kotlin/Java-код, JNI/llama.cpp, новые Android-разрешения, сервисы, Activity, новые сетевые протоколы и новые библиотеки требуют APK. Удалённая конфигурация не должна загружать или исполнять код.

## Безопасная схема будущего загрузчика

1. Получить `manifest.json` по HTTPS из доверенного raw URL.
2. Проверить `schemaVersion`, `minimumAppVersion`, размер каждого файла и SHA-256.
3. Отклонить неизвестные поля критических структур, чрезмерные значения и пути за пределами каталога конфигурации.
4. Сначала загрузить весь набор во временный каталог.
5. Проверить JSON и контрольные суммы до переключения активной версии.
6. Сохранить последнюю рабочую конфигурацию для отката.
7. При сетевой ошибке продолжить работу с локальной последней рабочей конфигурацией.
8. Не загружать и не выполнять скрипты, APK, DEX, JAR, SO или другой исполняемый контент.

API-ключ Gemini и Android Keystore никогда не должны попадать в этот каталог. Секреты хранятся только локально на устройстве.

## Публикация и проверка

Изменения вносятся в GitLab, проходят MR, затем зеркалируются в GitHub. Изменения только в runtime-config, документации и скриптах проверки не запускают Android APK build. Изменения Android-кода, Gradle и нативной части запускают сборку. Пока загрузчик не внедрён, runtime-файлы являются подготовленной конфигурацией, а не активным удалённым управлением.


## Дополнительные runtime-пакеты

- `response_profiles.json`: компактный, подробный, технический и голосовой формат ответа.
- `privacy.json`: запрет фоновой передачи вложений, API-ключей и пользовательских данных.
- `voice.json`: параметры распознавания, план wake-word «Джимми» и TTS. Wake-word и TTS остаются выключенными до реализации соответствующего Android-кода.
- `network.json`: таймауты и правила работы при отсутствии сети.
- `diagnostics.json`: лимиты журналов и исключение секретов из диагностики.

Эти файлы описывают настройки для будущего загрузчика. Они не включают отсутствующие функции сами по себе.
