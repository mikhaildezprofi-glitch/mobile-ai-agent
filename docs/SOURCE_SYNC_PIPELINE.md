# GitLab → GitHub → GitLab → Android

## Поток сборки

1. Исходники проекта ведутся в GitLab.
2. Изменения, предназначенные для синхронизации, публикуются в ветке `sync/*`.
3. Push в соответствующую ветку GitHub запускает workflow **Android APK Build**.
4. GitHub Actions собирает debug APK, вычисляет SHA-256 и формирует `build-metadata.json` с исходным SHA, версией, размером и идентификатором запуска.
5. Для push в `sync/*` GitHub публикует APK, checksum и metadata в Release с уникальным тегом, содержащим префикс исходного SHA.
6. GitLab job `github-apk-sync` ищет Release для точного `CI_COMMIT_SHA`, скачивает три артефакта и сверяет все контрольные суммы.
7. Только после успешной проверки APK artifact в GitLab можно передавать на устройство.

GitLab не запускает APK-sync job для произвольных Merge Request или обычного push в `main`: GitHub workflow не публикует для них Release, поэтому ожидание такого Release было бы бесполезным расходом CI-квоты.

## Установка на устройство

APK из GitHub Actions подписан ключом runner. Перед обновлением подпишите его локальным Android debug keystore, проверьте fingerprint сертификата относительно установленного приложения и используйте `adb install -r`. Не удаляйте приложение и не очищайте его данные.

## Критерии подтверждения

- Полный SHA исходного коммита.
- GitHub workflow run и его conclusion.
- SHA-256 и размер APK.
- Успешный GitLab APK-sync job и наличие artifact.
- Версия установленного пакета.
- Отдельные runtime-проверки JNI, загрузки моделей, генерации текста и анализа изображения.

Успешная сборка не равна успешной работе приложения на телефоне.
