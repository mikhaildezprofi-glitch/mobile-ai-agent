# Инструменты PocketPal AI в Джимми

В Джимми перенесена и адаптирована архитектура PocketPal TalentRegistry / AgentRunner. Инструменты выполняются через структурированные function calls нативного движка, а не через JSON, спрятанный в обычном тексте ответа.

## Реализовано

- Реестр с явным allow-list.
- Структурированные OpenAI-compatible JSON schemas, передаваемые chat-template движка.
- Парсинг tool calls на стороне PocketPal llama.rn.
- Последовательное выполнение с жёстким лимитом пяти вызовов на запрос.
- Передача результата обратно модели в сообщении `role=tool` с исходным `tool_call_id`.
- Локальный калькулятор с ограниченным математическим парсером.
- Дата и время с проверкой IANA timezone.
- Unit-тесты схем, парсинга результата JNI и локальных инструментов.

## Интеграция

`AgentCoordinator.generate()` направляет локальные запросы в `PocketPalLocalProvider`. Планировщик, SQLite-журнал, возобновление задач и Gemini-маршрутизация сохранены. Каждый локальный шаг плана использует тот же структурированный tool runner.

Старый текстовый JSON-envelope runner удалён, чтобы не оставлять два конкурирующих механизма вызова инструментов.

## Безопасность

Зарегистрированы только `calculate` и `datetime`. Нет shell, ADB, произвольного доступа к файлам, сетевых запросов или Android-действий. Неизвестное имя инструмента возвращает ошибку и не исполняется.

## Ограничения

- Инструменты выполняются последовательно.
- В текущей реализации Kotlin получает итоговый ответ после завершения структурированного цикла; нативный bridge уже поддерживает snapshot callback, но потоковую передачу текста в UI ещё нужно подключить.
- Qwen3-1.7B требует отдельной проверки качества tool calling на реальном устройстве.
