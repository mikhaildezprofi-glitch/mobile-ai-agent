# MOBILE AI AGENT

Android AI-ассистент с локальным Qwen/llama.cpp и гибридной облачной маршрутизацией. Основная цель архитектуры — выполнять обычную текстовую работу в облаке, оставляя телефону только локальные задачи и функции, которым нужен доступ к устройству.

## Текущая версия: 0.3.8

### Реализовано в рабочей копии

- Локальный inference через llama.cpp и GGUF-модели.
- Единый `AgentCoordinator` для классификации запросов и выбора провайдера.
- Гибридный режим может работать даже при ошибке инициализации нативной библиотеки; локальный провайдер помечается недоступным, а Gemini продолжает обслуживать текстовые запросы.
- В гибридном режиме обычные текстовые запросы, код и сложный анализ направляются в Gemini 3.5 Flash-Lite, если API-ключ настроен и доступна квота.
- При отсутствии сети, квоты или ключа запросы автоматически остаются на локальной модели. Если нативный движок вообще не инициализировался, гибридный режим всё равно может работать через Gemini.
- API-ключ Gemini шифруется Android Keystore и не хранится в Git.
- Вложения и файлы не отправляются в облако автоматически: выбранные документы и изображения обрабатываются локально.
- Безопасное чтение выбранных пользователем TXT, исходников, PDF и поддерживаемых офисных документов.
- Поддержка изображений через `libmtmd` llama.cpp: загрузка совместимого `mmproj`, токенизация изображений и обработка через vision-проектор.
- Подготовка изображений для MTMD vision и извлечение до четырёх кадров из видео.
- Фоновая генерация с уведомлением; CPU wake lock используется только для локальной инференции.
- Монитор производительности устройства.
- Termux worker с безопасным allowlist команд, heartbeat раз в 15 минут и локальный монитор.
- GitHub Actions проверяет доступность телефона раз в час. Задачи, не требующие телефона, не должны ждать восстановления ADB.

### Облачная маршрутизация

- **Gemini:** обычный текст, программирование и сложное рассуждение в гибридном режиме.
- **Qwen/llama.cpp:** локальный режим, резервный ответ при недоступности облака, а также обработка выбранных файлов и изображений.
- **Поиск в интернете:** ещё не подключён к приложению. Не выдавай ответ локальной модели за проверенную актуальную информацию.
- **Управление Android:** исполнитель действий и подтверждения пользователя ещё не подключены.

Для облачного режима нужен API-ключ Google AI Studio. Бесплатная квота ограничена и зависит от доступности модели и региона; при её исчерпании приложение переключается на локальную модель. Передача вложений в облако не включена.

### Работа с изображениями и видео

Для анализа изображений используется нативный `libmtmd` backend. Нужны совместимая vision-модель (в проекте предусмотрен SmolVLM 500M) и соответствующий `mmproj`. Приложение считает vision готовым только после успешной загрузки проектора; если загрузка не удалась, оно сообщает об ограничении и не изображает, будто увидело файл.

Видео не передаётся модели целиком. Приложение извлекает до четырёх кадров из ролика, уменьшает их до безопасного размера и передаёт как изображения. Вывод описывает только выбранные кадры, а не непрерывное движение или звук.

## Сборка APK в облаке

Сборка выполняется GitHub Actions, а не на телефоне:

1. Открой репозиторий и вкладку **Actions**.
2. Запусти **Android APK Build** или создай pull request в `main`.
3. После успешной сборки скачай artifact `mobile-ai-agent-debug-apk`.
4. Установи APK на Android и проверь запуск.

CI использует JDK 17, Gradle 8.14.3, Android SDK 36 и NDK 29. Патч Android native backend отключает OpenMP на arm64, включает `LLAMA_BUILD_MTMD`, подключает `libmtmd` и vision JNI-интерфейс. Это устраняет причину неразрешённых символов `__kmpc_*` и включает реальную обработку изображений через projector.

## Важные ограничения

- Успешная компиляция не подтверждает успешную загрузку модели: нативный запуск нужно отдельно проверить на устройстве.
- Видеозвук и полная покадровая обработка пока не реализованы.
- Действия Android требуют отдельной проверки разрешений и явного подтверждения.
- При аварийном завершении сохраняется уже полученный текст, но нативная генерация не возобновляется с того же токена.
- GGUF-модели и сторонний `llama.cpp` не включаются в Git; они остаются локальными или загружаются CI.
