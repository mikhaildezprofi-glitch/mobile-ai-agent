# GitLab AI agent control

GitLab is the primary development and orchestration platform. Copilot profiles are not used as executors here.

## Executor

- Aider is the open-source coding agent.
- Model: Gemini 3.8 Flash through the Gemini API Free tier.
- GitLab CI runs the agent in an isolated job.
- Every task has a role, acceptance criteria, and a strict editable-path allowlist.
- The agent can create a branch and Draft Merge Request, but cannot merge or write to `main`.
- Only one task may be queued or under review at a time.

## Required CI/CD variables

Create these in **Settings → CI/CD → Variables**. Mark both Masked and Protected; do not put them in repository files.

- `GEMINI_API_KEY`: Google AI Studio API key on the Free tier.
- `GITLAB_AGENT_TOKEN`: project access token with `api` and `write_repository` scopes. Use the minimum role that can push branches and create Draft MRs.

No billing account or card is required for the Gemini Free API tier when the account/project is eligible. Free-tier quotas can be limited and can change. Do not send secrets, personal data, signing material, private logs, or model files to the free API.

## Enable the first task

1. Add the two masked/protected CI variables.
2. Review the queue task and change its status from `blocked` to `queued` only after the executor credentials are configured.
3. Run **Build → Pipelines → Run pipeline** on the default branch.
4. Start the manual `gitlab-ai-agent` job.
5. Review the Draft MR and its CI evidence. Never auto-merge.

## Hourly monitoring

Create one GitLab pipeline schedule for the default branch:
- Cron: `0 * * * *`
- Timezone: `UTC`
- Description: `Hourly project, CI, queue and agent monitor`

The schedule runs the read-only `project-hourly-monitor` job. CI schedules are configured in the GitLab UI; a cron entry in a YAML file alone does not create a schedule.

## Security boundaries

- The worker does not execute shell commands generated by the model.
- The model receives only the task's allowlisted writable files and read-only repository context.
- Any changed path outside the allowlist causes the job to stop before commit.
- No direct writes to `main`, no auto-merge, no destructive operations.
- A CI job is not counted as an AI agent session; a real task must produce a branch and Draft MR.
